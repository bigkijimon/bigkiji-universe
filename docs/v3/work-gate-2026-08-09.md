## 扉1 ― 分類。同じ依頼が、漢字で書いたかどうかで消えていた

`heuristicKind()` が見ていたのは 14 語だけ。
さらに `guardedKind()` が**モデルの TASK を無条件で CHAT に降格**していた（ログに毎ターン
`model says TASK -> final: CHAT`）。

| オーナーが打った文 | 判定 |
|---|---|
| `課金トークンのリミット解除されてるか確認して欲しいす` | **CHAT**（runなし） |
| `課金トークンのリミットを確認してほしい` | **TASK**（runあり） |

違いは **欲しい / ほしい の一箇所**。Subagent 自体は健全で、
`model_performance.json` には codex 76回・glm 84回の実行記録がある。呼ばれていなかっただけ。

### 直したこと

1. **表記ゆれの正規化**（`normalizeRequest`）— 欲しい→ほしい / 下さい→ください /
   出来る→できる / 頂け→いただけ / 貰え→もらえ。原文は書き換えない、判定のためだけ。
2. **二段目の語彙**（`actionTier`）— 作業語（確認・調べ・一覧・セットアップ…）が
   **依頼の締め**（〜て / 〜てください / 〜ておいて / 〜お願い）と組んだときだけ TASK。
   締めから 24 文字の窓に作業語を要求するので、`今日は確認が取れなくて、疲れた` は CHAT のまま。
3. **モデルの昇格を認める**（`classifyKind`）— ただし `promotedByModel: true` を付ける。

### 昇格の代金は承認 1 回（これが取引の要）

`daemon.js` は `promotedByModel` の run を **`mode: 'plan'` で submit する**。
`auto-edit` でも AWAITING_APPROVAL で止まる。3B の分類器に判断させる代わりに、
間違いは**プロンプト 1 回で払い、編集では払わない**。
経由する front desk（`fast-api-router.js`）は `runOllama` = ローカル無料なので、
誤昇格に課金は発生しない。

**それでも昇格しないもの**: 「お願いします」だけの一行。
goal が「お願いします」の計画は承認キューのゴミで、`/approve` 一回で課金 run になる。
go-ahead は `isAffirmative` の専用経路が答える。

### 語彙を広げて壊れかけたもの

`status-answer.js` は `heuristicKind(...) === 'TASK'` で状況質問の横取りを止めていた。
確認・調査は状況質問を作る語でもあるので、そのまま共有すると **「進捗を確認して」がモデルに流れる**
——この file が存在する理由そのものを壊す。`actionTier(...) === 'strong'` に変更し、
共有するのは一段目だけにした。

## 扉2の後ろ ― 書いている様子が見えない

step は tool 名・ファイル・`+12 −3` までしか運んでいなかった。
何かが起きたことは分かるが、**止める判断ができない**。

- `stream-steps.js` に `patchOf()` を追加。Edit は old/new から、Write は content から、
  patch を持つ provider はそのまま。**上限 40 行 / 4000 文字**で、切った分は
  `… +N more lines (not shown)` と明記する（黙って切ると完全な差分に見える）。
  step は全サーフェスに publish され session jsonl にも追記されるので、上限は必須。
- `transcript.js` の `step` が `formatDiff` で本文を描く。
- CLI は端末の高さの 1/3（4〜16行）を `diffLines` として渡す。step はオーナーが入力中に
  流れるので、40 行の diff は自分のプロンプトを画面外に押し出す。

### 待っていることが画面に出る

front desk が質問を保留している間、phase は直前の run のままだった。
footer に `awaitingAnswer` を追加し、状態語は **`asking`**、コメント欄は

## ギャップ1・2 も同日に埋めた

**実行中の相互通信** — 「後から結果をプロンプトに差し込む」は取れない。
`createDisclosureManifest` が prepared prompt を `payloadHash` に焼き、
`verifyDisclosureManifest` が起動時に再検査する（task-runner.js:157）。
承認後にプロンプトを書き換えるのは、承認ゲートを迂回することと同じ。

**だから承認するのは「経路」で、生きているのは中身だけ**にした。
`_handoffDir(run)` = `<cwd>/.bigkiji/handoff/<runId>/`。プロンプトはこのパスと作法を書くだけ
なので文言は不変＝payloadHash も不変。**ノートは coordinator 自身が書く**——
モデルに「終わったら書いてね」と頼む方式は、run が荒れたときにちょうど欠ける。
届く範囲は正直に: 同時に走り出した者同士は今も盲目。効くのは `maxParallel` で待たされた
assignment・repair サイクル・フォールバック再試行——**誰かが既に終わっている場合**だけ。
run の終了時に `forgetRun` が消す（残すと worktree 35GB と同じ道）。

**成果の統合** — 自動マージはしない判断は妥当なので、**人向けに統合**した。
`buildReport` の各 row が `diff`（60行/6000字で打ち切り・切った分は明記）を持ち、
`transcript.js` が役割ごとに1画面へ並べる。マージはオーナーの操作のまま。

## 追記 2026-08-10 — 同じ日の修正の中から出てきた欠陥

上の修正を全数点検して見つかった分。**「片方の扉だけ代金を払っていなかった」のが本丸**。

### soft 語彙が auto-edit で課金 run を出していた

`daemon.js` は `promotedByModel ? 'plan' : mode`。モデル昇格は承認1回を払うのに、
**同じ日に広げた soft 語彙は払っていなかった**。オーナー実コーパス361件で再測定すると、
soft が新たに拾う15件のうち3件は仕事ではない——
`こんにちは 今日は何ができますか…` / `how can you run btw` / `日本の首都について三行で教えてください`。
その午後に書いた正規表現が、それが肩代わりしたはずのモデルより信用されていた。
オーナー判断（2026-08-09）で **soft も `plan`**。`strong` は据え置き——
「修正して」に承認を挟むのは「何も始まらない」に戻る道。

`how can you run btw` は soft からも外した。日本語は締めの近くに作業語を要求するのに、
英語だけ `EN_REQUEST` と `EN_WORK` を文中どこでも当てていた（`can you` ＋ `run`）。
疑問詞が助動詞の直前に来ていれば能力への質問。`can you check the rate limit?` は依頼のまま。

### 凍結中でも「local-qwen が使えます」と答えていた

`provider-readiness.js` の「導入済みか」を `providerReport()` の「いま応答できるか」に流用していた。
`ps` が T を示している横で 6社使えると答える——**実測で答えるために作った経路が推測していた**。
`Daemon#frozenProviders()` が usable から外し、ロックの保持者と時刻を添えて `frozen` に移す。
`frozenWithoutLock()`（書かれて一度も呼ばれていなかった）が「誰も解凍しない凍結」を区別する。

### コールドロードをストールとして数えていた（ギャップ3の片方）

`timeoutMs` はトークン間の沈黙の期限なのに、**まだロードされていないモデルの沈黙**も
そこに課金されていた。`firstTokenTimeoutMs = 20000` を分離（実測 9.2 秒の倍）。
keep_alive は上げない——VRAM を握り続けるのは全社GPU調停ルールに反する。

### 前受付が候補名と違うものを走らせる寸前だった

候補ループは候補が何であれ `runOllama` を呼んでいた。`detect()` が glm 以下を false 固定
だったので顕在化していなかっただけで、実プロバイダを足した瞬間
「provider=glm と記録して中身はローカルが書いた」になる。ディスパッチ表に変更。
`runOllama` に AbortController も無かった（`ollamaReady()` の 850ms が前で守っていただけ）。

### GPUが埋まっている間だけ GLM-4.7-flash に逃がす（オーナー依頼）

`conversation.cloudFallback: 'off' | 'gpu-busy'`。既定は off。
GPUが空いていれば必ずローカル。送る前に `redactPayload`、コマンドは
`pi --print --no-tools --no-context-files --no-session --no-skills`＝プロンプト1本だけが出る。
**返答の先頭に「クラウドに出しました」と明記する**。課金 run の経路（disclosure manifest）は不変。

### 共有GPUスクリプトの `head -1`（app/ の外）

`mem-switch.sh` の `get_pid()` と `ollama-watchdog.sh` が `pgrep -f ... | head -1` で
**1本にしかシグナルを送っていなかった**。修正当日の実測がまさにその状態:

```
 1190 T  .../Resources/ollama          ← 親も凍結
48526 T  .../Resources/llama-server    ← 凍ったまま
72755 S  .../Resources/llama-server    ← 凍っていない
```

freeze 側は GPU が空かず（ComfyUI の OOM 要因）、thaw 側は取り残しを作る。
取り残された方はロックが無いので番人も起こさない＝`frozenWithoutLock` の正体。
両方を全PIDループに変更し、`mem-switch status` も全部を並べるようにした。

**修正後、同じレンダの次のショットで実測（00:57・こちらは何もしていない）:**

```
$ ps -Ao pid,stat,comm | grep -E 'llama-server|Resources/ollama'
 1190 T  .../Resources/ollama
48526 T  .../Resources/llama-server
72755 T  .../Resources/llama-server     ← 修正前はここが S のまま残っていた

$ node -e "…providerFacts()"
usable : claude-code, codex, gemini, glm, pi-agent-core
frozen : [{"provider":"local-qwen","holder":"u09-v5","since":"21:32:48","orphaned":false}]

いま使えるのは claude-code / codex / gemini / glm / pi-agent-core の 5 社です。
  local-qwen  停止中（GPUを「u09-v5」が21:32:48から使用中。終われば戻ります）
```

3本とも T ＝ **レンダが初めて GPU を丸ごと受け取っている**。そして BKU は
「6社使えます」ではなく「5社＋local-qwenは停止中、理由はこれ」と答えている。
