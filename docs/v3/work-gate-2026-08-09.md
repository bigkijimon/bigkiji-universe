## 扉1 ― 分類。同じ依頼が、漢字で書いたかどうかで消えていた

`heuristicKind()` が見ていたのは 14 語だけ。
さらに `guardedKind()` が**モデルの TASK を無条件で CHAT に降格**していた（ログに毎ターン
`model says TASK -> final: CHAT`）。

| オーナーが打った文 | 判定 |
|---|---|
| `課金トークンのリミット解除されてるか確認して欲しいす` | **CHAT**（runなし） |
| `課金トークンのリミットを確認してほしい` | **TASK**（runあり） |

違いは **欲しい / ほしい の一箇所**。Subagent 自体は健全で、
`model_performance.json` には codex 76回・glm 84回の実行記録がある。呼ばれていなかっただけ。

### 直したこと

1. **表記ゆれの正規化**（`normalizeRequest`）— 欲しい→ほしい / 下さい→ください /
   出来る→できる / 頂け→いただけ / 貰え→もらえ。原文は書き換えない、判定のためだけ。
2. **二段目の語彙**（`actionTier`）— 作業語（確認・調べ・一覧・セットアップ…）が
   **依頼の締め**（〜て / 〜てください / 〜ておいて / 〜お願い）と組んだときだけ TASK。
   締めから 24 文字の窓に作業語を要求するので、`今日は確認が取れなくて、疲れた` は CHAT のまま。
3. **モデルの昇格を認める**（`classifyKind`）— ただし `promotedByModel: true` を付ける。

### 昇格の代金は承認 1 回（これが取引の要）

`daemon.js` は `promotedByModel` の run を **`mode: 'plan'` で submit する**。
`auto-edit` でも AWAITING_APPROVAL で止まる。3B の分類器に判断させる代わりに、
間違いは**プロンプト 1 回で払い、編集では払わない**。
経由する front desk（`fast-api-router.js`）は `runOllama` = ローカル無料なので、
誤昇格に課金は発生しない。

**それでも昇格しないもの**: 「お願いします」だけの一行。
goal が「お願いします」の計画は承認キューのゴミで、`/approve` 一回で課金 run になる。
go-ahead は `isAffirmative` の専用経路が答える。

### 語彙を広げて壊れかけたもの

`status-answer.js` は `heuristicKind(...) === 'TASK'` で状況質問の横取りを止めていた。
確認・調査は状況質問を作る語でもあるので、そのまま共有すると **「進捗を確認して」がモデルに流れる**
——この file が存在する理由そのものを壊す。`actionTier(...) === 'strong'` に変更し、
共有するのは一段目だけにした。

## 扉2 ― どのAIが使えるかを、答えが手元にあるのにモデルに聞いていた

`circuit-breaker.json` に生きたクールダウン、`model_performance.json` に
`throttledReason: "rate-limit"` があるのに、`facts()` は 4 社すべてを
「providers that can run work」として渡していた。

- `CircuitBreaker#openCircuits()` を追加（純粋クエリ。half-open のトライアルを消費しない）
- `Daemon#providerFacts()` で fleet / breaker / performance の 3 つを結合

- `_turn` で**分類より前**に横取り。語彙拡張後は「確認して欲しい」が TASK なので、
  そうしないと**レート制限を調べるために課金 run を 1 本使う**

### `connected` は「忙しい」ではない

`model-status-store.js:53` は常駐なので `pi-agent-core` の `connected` を true に固定する。
`facts()` はそれを「いま作業中」として渡していたので、
画面には**アイドルのマシンが自分を忙しいと言う**「pi-agent-core が忙しく…」が出ていた。
busy は runner の `status === 'running'` から取るように変更。

## 扉2の後ろ ― 書いている様子が見えない

step は tool 名・ファイル・`+12 −3` までしか運んでいなかった。
何かが起きたことは分かるが、**止める判断ができない**。

- `stream-steps.js` に `patchOf()` を追加。Edit は old/new から、Write は content から、
  patch を持つ provider はそのまま。**上限 40 行 / 4000 文字**で、切った分は
  `… +N more lines (not shown)` と明記する（黙って切ると完全な差分に見える）。
  step は全サーフェスに publish され session jsonl にも追記されるので、上限は必須。
- `transcript.js` の `step` が `formatDiff` で本文を描く。
- CLI は端末の高さの 1/3（4〜16行）を `diffLines` として渡す。step はオーナーが入力中に
  流れるので、40 行の diff は自分のプロンプトを画面外に押し出す。

### 待っていることが画面に出る

front desk が質問を保留している間、phase は直前の run のままだった。
footer に `awaitingAnswer` を追加し、状態語は **`asking`**、コメント欄は
**`answer to start`**。`_measuredTurn` は保留中の質問を**消費しない**ので、
質問が出ている最中に「進んでる？」と聞いても、状況が返り、質問は生きたまま残る。

## ギャップ1・2 も同日に埋めた

**実行中の相互通信** — 「後から結果をプロンプトに差し込む」は取れない。
`createDisclosureManifest` が prepared prompt を `payloadHash` に焼き、
`verifyDisclosureManifest` が起動時に再検査する（task-runner.js:157）。
承認後にプロンプトを書き換えるのは、承認ゲートを迂回することと同じ。

**だから承認するのは「経路」で、生きているのは中身だけ**にした。
`_handoffDir(run)` = `<cwd>/.bigkiji/handoff/<runId>/`。プロンプトはこのパスと作法を書くだけ
なので文言は不変＝payloadHash も不変。**ノートは coordinator 自身が書く**——
モデルに「終わったら書いてね」と頼む方式は、run が荒れたときにちょうど欠ける。
届く範囲は正直に: 同時に走り出した者同士は今も盲目。効くのは `maxParallel` で待たされた
assignment・repair サイクル・フォールバック再試行——**誰かが既に終わっている場合**だけ。
run の終了時に `forgetRun` が消す（残すと worktree 35GB と同じ道）。

**成果の統合** — 自動マージはしない判断は妥当なので、**人向けに統合**した。
`buildReport` の各 row が `diff`（60行/6000字で打ち切り・切った分は明記）を持ち、
`transcript.js` が役割ごとに1画面へ並べる。マージはオーナーの操作のまま。
固定 = `tools/handoff-selftest.js`。
